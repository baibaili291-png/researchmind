# ResearchMind · 自主深度研究 Agent

> 个人项目 / 独立完成 · 2026

**一句话描述**：输入一个研究问题，系统自动完成问题拆解、联网检索、网页正文抓取、事实抽取、交叉验证与报告撰写，输出每条事实都带可追溯引用的深度研究报告。

---

## 技术栈

`Python 3.10+`（核心零第三方依赖，仅标准库）· `SQLite` · `SSE` 服务端推送 · 原生 `JavaScript / HTML / CSS` · `DeepSeek API`（OpenAI 兼容）· `Docker / Compose`

---

## 项目背景与目标

通用大模型直接写行业研究报告有两个硬伤：**事实不可追溯**、**数字口径混用**。同一篇报告里并列着"212 亿"和"804 亿"两个市场规模，读者无从判断哪个可信。

本项目要解决的不是"能不能写出一篇像样的报告"，而是**报告里的每句话能不能被验证**。因此系统的核心约束是：不允许模型自由发挥，所有事实性陈述必须绑定到一段可逐字核对的原文。

## 我的工作

### 1. 设计带环的状态机主流程

`plan → search → fetch → extract → verify → route → write → cite`，其中 `route` 是条件边：验证阶段若发现数字冲突或某个维度证据不足，会**回退到检索阶段**并生成针对性追问，最多迭代 3 轮。这让系统从"一次性生成"变成"发现问题→补证据→再写"。

### 2. 把「证据账本」做成一等公民

写入顺序固定为 **抽取 → 校验 → 入账 → 写作 → 引用审计**，任何环节不得越过账本直接写作。三条确定性校验（纯函数，不依赖模型）：

- 引文必须是原文的**逐字连续子串**，改写或拼接一律拒绝
- 同一主题下的数值偏差超过 8% 记为**数据冲突**，报告中必须并列两种口径，不得取平均
- 报告中的 `[E#]` 引用必须能解析到账本条目，**悬空引用数必须为 0** 才允许交付

最终报告 261 处引用、0 悬空，覆盖率可审计。

### 3. 设计三层降级与供应商可替换架构

搜索、抓取、LLM 全部做成适配器，任一层失败自动回退：`httpx → trafilatura 正文提取 → Playwright 渲染 → Reader API`。目标是**部分失败不导致整体失败**——某个站点反爬，报告仍然出得来，但必须在「研究局限」里如实说明哪些维度没拿到证据，而不是编造填补。

### 4. 治理「静默失败」——本项目最有价值的工程经验

开发中遇到三类"看起来成功、实际残缺"的故障，都出在**没有把失败当失败**：

| 故障现象 | 根因 | 处理 |
|---|---|---|
| 报告状态显示成功，正文却断在半句话 | 整篇报告一次生成，触及 `max_tokens` 上限被硬切；且只在返回内容**为空**时才检查 `finish_reason`，非空截断被当作成功 | 改为逐章生成 + 参考资料确定性渲染；新增截断检测，遇 `length` 抛错触发翻倍重试 |
| 七个章节有五章空白 | 并发抽取时 API 限流，异常被 `except` 吞掉返回空列表，与"这页没有相关内容"无法区分 | 返回值区分 `(证据, 是否成功)`，失败计数并告警，降低并发并加重试 |
| 报告生成过，页面却显示"等待任务" | run 记录只存进程内存，重启即清空 | 报告落盘、启动时回读、前端自动加载最近一份 |

**结论沉淀**：状态字段必须能表达"未知"和"失败"，否则它一定会撒谎。

### 5. 性能优化：519s → 248s（同证据量）

先用埋点测出各阶段真实耗时，而不是凭直觉改：

```
search 3.5s | fetch 70.6s | extract 107s + 43s | write 176s
```

四处针对性改动：

- **写作并发化**（176s → 44s）：摘要与各章节互不依赖，放进同一线程池
- **抽取并发化 + 主线程保序入账**：LLM 调用并发执行，结果按原顺序在主线程合并，证据编号仍确定、去重集合无需加锁
- **砍掉无效抽取**：每维度限制喂给抽取器的文档数；已产出证据的（来源，子问题）组合不再重抽
- **消除隐藏阻塞**：关闭 Playwright 兜底（单页启动浏览器 5–15s），搜索限速冷却 25s → 4s

## 工程取舍

- **零依赖优先**：核心链路只用标准库，`python -m backend.api.server` 即可运行。目的是保证"clone 下来就能跑"，不被依赖地狱拖住。
- **确定性优于聪明**：校验逻辑写成纯函数而非再问一次模型。模型可以生成候选，但不能决定真假。
- **宁可少写，不可编造**：证据不足的章节明确写"未获得通过校验的证据，故不输出结论"，而不是用泛泛而谈填充。
